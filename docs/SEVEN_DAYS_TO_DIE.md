# Seven Days to Die requirements inventory

This is the evidence inventory for #32, read alongside the experimental adapter
(#164) and its planner proof (#165). It does not certify a runtime or select new
platform designs. Arcadectl evidence below is pinned to main commit
`0225dc4a1da171b3aa07028ab8e94e7e77ea8cf5` (2026-11-03 inspection).
Relative source links name files at that snapshot; later changes need a new audit.

Classifications describe the requirement, not whether a 7DTD adapter is installed:
`supported` means an existing generic primitive; `adapter data` means a curated
adapter or certified image can express it; `new typed capability` means a generic
contract needs separate design; `unsupported` means an explicit non-goal with the
failure behavior stated. The production [catalog](../internal/catalog/catalog.go)
currently registers Factorio only. None of the rows grants production 7DTD support.

All upstream links were accessed **2026-11-03**. Source age matters: the official
support FAQ's port table was edited 2025-12-12; A21 release notes establish changes,
not current binary defaults. The moderator's 2022 bundled-config sample is
historical evidence. No current server binary or shipped config was downloaded
or run. **Unverified** identifies details requiring the selected version's config
and an owned runtime experiment; it is not permission to guess a default.

## Generic capability questions for separate design

These are review inputs, not selected interfaces or implementation instructions.
Each new typed capability row above maps to one note here; #32 tracks the
follow-up design work before real-game certification.

- **W — create-only world identity.** Factorio map/seed choices, synthetic seed
  identity and 7DTD world/save/generation selectors all need a distinction between
  ordinary runtime configuration and a deliberate new-world operation. Review a
  generic immutable-on-existing-data policy and explicit recreation intent rather
  than comparing game-specific keys in the controller. **Threat:** a settings
  update must not silently select or generate an empty world beside retained data.
- **S — bounded clean stop.** Certify Factorio's existing image stop behavior,
  exercise success/timeouts with synthetic, and determine 7DTD's save/exit protocol
  on the chosen image. Review a bounded image-local stop contract and grace budget;
  do not add user-controlled shell fragments or open telnet to the network.
  **Threat:** a deadline or failed save must not be reported as a clean stop or
  certify a corrupt cold backup; commands and credentials must stay private.
- **C — game secret references.** Factorio public-listing credentials, synthetic
  fake rotation/refusal fixtures and 7DTD join/admin credentials need the same
  reference, authorization, projection and redaction boundary. Review namespace
  scoping and rotation without exposing values in settings, ConfigMaps, Events or
  diagnostics. **Threat:** cross-tenant reference confusion, backup disclosure and
  credential logging; neither a raw XML field nor the API bearer token is a safe
  shortcut.
